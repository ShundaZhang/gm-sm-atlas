SM3 与 SHA-256 的字宽、分组和轮数相同，但 IV、常数、扩展、布尔函数阶段、状态更新及最终前馈不同。SHA-512 不是把 SHA-256 输出缓冲加倍，它使用 64 位字、不同旋转、更大分组及 80 轮。SHA-512/256 有独立 IV，不是简单截断普通 SHA-512。

02 / FIELD NOTES

SHA-256 压缩使用不同函数及常数

它有八个工作字，但没有 SM3 的 P0 / P1。

SHA-256 (32-bit ROTR):
Ch(x,y,z)=(x & y) XOR (~x & z)
Maj(x,y,z)=(x & y) XOR (x & z) XOR (y & z)
σ0(x)=ROTR(x,7) XOR ROTR(x,18) XOR (x >> 3)
σ1(x)=ROTR(x,17) XOR ROTR(x,19) XOR (x >> 10)
Wj=σ1(Wj−2)+Wj−7+σ0(Wj−15)+Wj−16 mod 2³²
Σ0(a)=ROTR(a,2) XOR ROTR(a,13) XOR ROTR(a,22)
Σ1(e)=ROTR(e,6) XOR ROTR(e,11) XOR ROTR(e,25)
T1=h+Σ1(e)+Ch(e,f,g)+Kj+Wj mod 2³²
T2=Σ0(a)+Maj(a,b,c) mod 2³²
new a=T1+T2; new e=d+T1 (mod 2³²)
Other registers shift; final chaining words ADD old words

SHA-256 使用 64 个不同轮常数，而不是 SM3 按轮号旋转的两个基础常数。二者解析 32 位字时恰巧都是大端，这可能让正确字节处理掩盖错误核心。应分别使用各算法已知答案，而不是只检查摘要长度。

03 / FIELD NOTES

SHA-3 吸收、置换并挤出

SHA3-256 的 rate=1088、capacity=512 位。

Keccak-f[1600]: 5×5 lanes, each 64 bits
Each of 24 rounds: θ → ρ → π → χ → ι
Absorb: XOR each padded 136-byte block into the rate lanes
Permute the whole 1600-bit state
Squeeze: read 32 digest bytes from rate
SHA3 byte-aligned suffix: 06; final padding bit: 80
Lane byte order: little-endian

θ 混合列奇偶，ρ 旋转 lane，π 重新排列 lane，χ 是非线性行变换，ι 将轮常数异或到一个 lane。消息不直接填充 capacity。SHA3 域后缀使它不同于原始 Keccak-256；即使置换、rate、输出长度相同，摘要也不同。

SHAKE128 / SHAKE256 是输出长度可变、域分离不同的 XOF。SHAKE256 名称不指定 256 位摘要；应用须请求足够输出并遵循构造规则。KMAC 是明确定义的带密钥 SHA-3 构造，不是任意秘密前缀。

04 / FIELD NOTES

普通杂凑不是加密，也不是 MAC

应明确安全目标与输出长度。

理想 256 位摘要的通用经典碰撞搜索约需 2¹²⁸ 工作量、原像搜索约 2²⁵⁶。这些是通用界限 / 模型，不是每个算法或实现均达到它们的证明。SHA-512 输出 512 位，通用界限不同；SHA3-256 的海绵分析还依赖 capacity。不能凭雪崩截图或玩具计时给算法安全性排名。

SM3 与 SHA-256 暴露类似 Merkle–Damgård 的链接状态，当 secret||message 摘要被误作认证时可出现经典长度扩展。应使用 HMAC 或规定 MAC。标准 SHA-3 不暴露完整海绵状态，没有同样普通长度扩展行为，但无密钥哈希仍不因此成为认证。
