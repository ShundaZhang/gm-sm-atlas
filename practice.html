01 / FIELD NOTES

Run a complete local reference project

No package installation is required for the Python core.

Download reference project ZIP ↓

cd gm-sm-atlas-examples
python3 -B test_reference.py
python3 -B demo.py

Requires Python 3.9 or newer. The code includes SM3 compression, SM4 expansion/encryption/decryption, AES-128 encryption, curveSM2/P-256 point arithmetic, SM2 signature/verification, C1C3C2 encryption/decryption and the SM2 exchange algebra with confirmation tags. SHA-256/SHA3-256 comparisons in the CLI use Python hashlib.

All fixed private scalars and nonces in examples are deliberately public synthetic test values. Do not use them as real keys and do not enter private keys into the browser labs. The reference is readable, bounded teaching code with no constant-time guarantee, not a certified cryptographic module.

02 / FIELD NOTES

Known answers plus an independent implementation

Ten test methods cover many values and rejection paths.

CheckEvidence
SM3abc and 64-byte published vectors; 10 OpenSSL-checked lengths around padding boundaries
SM4 / AES-128Published single-block answers and 8 independent key/block pairs for each cipher
SM2 signatureHistorical-draft known answer with its explicitly different test curve; current curve bidirectional OpenSSL verification
SM2 encryptionOpenSSL encrypt ↔ reference decrypt and the reverse, with explicit raw/DER conversion
Failure pathsWrong message/ID, bad points, zero r, tampered C2/C3, forbidden scalar and oversize ID
ExchangeA/B shared key and confirmation equality; changed identity changes derived key

Independent checks used OpenSSL 3.6.2. If the CLI is absent, the two independent test methods are explicitly skipped; the known-answer tests still run. If an installed OpenSSL lacks an algorithm, the independent test fails rather than pretending success. Exchange is algebraically cross-checked between sides; it is not independently certified or a network protocol test.

03 / FIELD NOTES

Inspect exact outputs before changing the implementation

A small intentional change should break the relevant known answer.

Try changing SM3’s final XOR to addition or its P1 rotation; inspect why abc fails. Change SM4’s L′ into L and observe the first round-key mismatch. Swap the SM2 signature ID and see verification reject. Compare the same scalar multiple on SM2 and P-256; the points differ because the domains differ. Restore the original code and rerun the checks.

Read rejection tests as security properties, not just exceptions to silence. A complete production deployment would additionally need side-channel evaluation, protocol interoperability and assurance appropriate to its application.

Read the source: NIST SP 800-56A Rev.3 ↗ · GmSSL · upstream implementation ↗
