01 / FIELD NOTES

ZUC 生成有状态密钥流

流密码不是 128 位分组密码。

原始 ZUC-128 核心输入 128 位密钥及 128 位 IV，组合 16 级 31 位 LFSR、比特重组，以及含两个 32 位寄存器和 S 盒处理的非线性函数。LFSR 运算与 2³¹−1 相关，不是 SM3 / SM4 的模 2³² 字加法。初始化与工作阶段不同。

工作输出是 32 位密钥流字序列。加密时按所选配置将相应位与消息异或。重复密钥 / IV 会重复密钥流、暴露明文间关系。机密性本身不提供完整性。

对应资料：GSMA · ZUC and 128-EEA3 / EIA3 ↗ · SCA · algorithm standards announcement ↗

02 / FIELD NOTES

EEA3 与 EIA3 是核心的不同使用

消息计数器及无线上下文属于输入配置。

128-EEA3 提供移动通信机密性配置，128-EIA3 提供完整性配置。它们定义计数、承载、方向、长度等上下文如何编码，并非可互换的任意“ZUC 加密”调用。测试数据包含按位长度，仅按字节的测试工具可能遗漏错误。

ZUC 加密应与完整流密码或 CTR 机密性构造对比，完整性配置应与规定完整性算法对比。不指定模式或流量配置便比较“ZUC 与 AES”，会混淆层次。

对应资料：GSMA · ZUC and 128-EEA3 / EIA3 ↗ · NIST SP 800-38A · block cipher modes ↗

03 / FIELD NOTES

256 位 ZUC 配置有独立规范

不能给 ZUC-128 追加密钥字节来扩展。

3GPP 较新的 256 位算法集包含基于 ZUC 的 256-NEA6、256-NIA6、256-NCA6，位于 TS 35.246–35.248 标准族。它们是具有独立初始化、格式及测试数据的 Release 配置。应检查实际 Release 与文档版本，不能从 ZUC 名称推断兼容。

本网站解释 ZUC 模型及阅读路径，不提供完整无线协议实现。集成产品时，应同时阅读技术规范与发布者实施 / 使用条件。

对应资料：3GPP · 256-bit ZUC algorithm set ↗ · GSMA · ZUC and 128-EEA3 / EIA3 ↗
