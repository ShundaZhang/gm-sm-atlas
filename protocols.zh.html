01 / FIELD NOTES

TLS 握手包含四类算法决策

TLS 1.3 密码套件不命名签名算法。

层次RFC 8998 标识 / 功能
记录 AEAD + 握手哈希TLS_SM4_GCM_SM3 (0x00C6); TLS_SM4_CCM_SM3 (0x00C7)
签名方案sm2sig_sm3 (0x0708)

证书信任独立证书、证书链、身份、有效期及策略检查

RFC 8998 将国密算法用于 TLS 1.3，不是所有浏览器或 TLS 库的通用“开启国密”开关。证书密钥类型、transcript 签名、协商组及记录 AEAD 都须匹配精确配置。SM2 原语测试成功，不证明完整 TLS 握手可互操作。

02 / FIELD NOTES

协议决定 SM2 身份上下文

握手签名与证书验证可能使用不同 ID。

RFC 8998 为其规定握手用途定义 TLSv1.3+GM+Cipher+Suite 这一 TLS 配置 ID，并讨论对端证书验证常见的 1234567812345678，同时指出 CA 可能不同。不能把单一 ID 硬编码进所有签名操作；应匹配证书签发者配置及握手角色。

SM2 公钥 OID、sm2-with-SM3 签名 OID 与 TLS SignatureScheme 是不同标识。原始 64 字节签名在另一接口可能需要 DER。正确解析证书不证明信任其签发者，也不确认对端主机名。

对应资料：RFC 8998 · SM cipher suites for TLS 1.3 ↗ · RFC 5280 · X.509 ↗ · OpenSSL 3.5 · SM2 API ↗

03 / FIELD NOTES

TLCP 是独立的传输协议方向

共用原语不意味着共用握手。

GB/T 38636-2020 定义 TLCP。其握手及证书 / 密钥角色应按协议与所选配置阅读；部署可能区分签名与加密证书角色。不能将这些假设搬入 TLS 1.3，也不能把 TLCP 简化为 TLS 1.3 将 AES 换成 SM4。

互操作记录应包括库 / 版本、协议版本、套件、组、身份字节、证书角色、信任锚及编码。应比较实际协商值及拒绝日志，而非“支持 SM2/3/4”的宣传标签。

对应资料：GB/T 38636-2020 · TLCP ↗ · GmSSL · upstream implementation ↗ · RFC 8998 · SM cipher suites for TLS 1.3 ↗
