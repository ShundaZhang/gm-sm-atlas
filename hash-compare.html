Compare SM3, SHA-256, SHA-512 and SHA3-256

Same output length does not mean the same construction.

SM3 and SHA-256 share word width, block size and round count, yet differ in IV, constants, schedule, Boolean-function schedule, state updates and final feed-forward. SHA-512 is not SHA-256 with twice the output buffer: it uses 64-bit words, different rotations, larger blocks and 80 rounds. SHA-512/256 is a separate IV-defined variant, not naive truncation of ordinary SHA-512.

02 / FIELD NOTES

SHA-256 compression uses different functions and constants

It has eight working words but no SM3 P0/P1 functions.

SHA-256 (32-bit ROTR):
Ch(x,y,z)=(x & y) XOR (~x & z)
Maj(x,y,z)=(x & y) XOR (x & z) XOR (y & z)
σ0(x)=ROTR(x,7) XOR ROTR(x,18) XOR (x >> 3)
σ1(x)=ROTR(x,17) XOR ROTR(x,19) XOR (x >> 10)
Wj=σ1(Wj−2)+Wj−7+σ0(Wj−15)+Wj−16 mod 2³²
Σ0(a)=ROTR(a,2) XOR ROTR(a,13) XOR ROTR(a,22)
Σ1(e)=ROTR(e,6) XOR ROTR(e,11) XOR ROTR(e,25)
T1=h+Σ1(e)+Ch(e,f,g)+Kj+Wj mod 2³²
T2=Σ0(a)+Maj(a,b,c) mod 2³²
new a=T1+T2; new e=d+T1 (mod 2³²)
Other registers shift; final chaining words ADD old words

SHA-256 uses 64 different round constants rather than SM3’s two base constants rotated by round number. Endianness happens to agree for their parsed 32-bit words, which can hide a wrong-core implementation behind correct byte handling. Use known answers from each algorithm instead of just checking the digest length.

03 / FIELD NOTES

SHA-3 absorbs, permutes and squeezes

For SHA3-256, rate=1088 and capacity=512 bits.

Keccak-f[1600]: 5×5 lanes, each 64 bits
Each of 24 rounds: θ → ρ → π → χ → ι
Absorb: XOR each padded 136-byte block into the rate lanes
Permute the whole 1600-bit state
Squeeze: read 32 digest bytes from rate
SHA3 byte-aligned suffix: 06; final padding bit: 80
Lane byte order: little-endian

θ mixes column parity; ρ rotates lanes; π relocates lanes; χ is a nonlinear row step; ι XORs the round constant into one lane. Capacity is not directly filled by the message. The SHA3 domain suffix distinguishes it from original Keccak-256, which produces different digests despite the same permutation, rate and output size.

SHAKE128 and SHAKE256 are XOFs with variable output lengths and different domain separation. Naming SHAKE256 does not specify a 256-bit digest; applications must request sufficient output and follow the construction’s rules. KMAC uses a defined keyed SHA-3 construction, not an arbitrary secret prefix.

04 / FIELD NOTES

A plain hash is neither encryption nor a MAC

Security goals and output sizes must be stated explicitly.

For an ideal 256-bit digest, generic classical collision search is about 2¹²⁸ work and generic preimage search about 2²⁵⁶. These are generic ceilings/models, not proofs that every algorithm or implementation achieves them. SHA-512 offers a 512-bit digest with different generic bounds; SHA3-256’s capacity also matters to its sponge analysis. Do not rank algorithms from an avalanche screenshot or a toy timing measurement.

SM3 and SHA-256 expose a Merkle–Damgård-style chaining state and permit classical length extension when a digest is misused as authentication of secret||message. Use HMAC or a specified MAC instead. Standard SHA-3 does not expose the full sponge state and does not have the same ordinary length-extension behavior; that still does not turn an unkeyed hash into authentication.
