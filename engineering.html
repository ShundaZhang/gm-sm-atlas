01 / FIELD NOTES

Readable reference code and production code serve different purposes

Functional correctness does not establish resistance to leakage.

The downloaded affine ECC implementation branches on scalar bits, uses variable-time Python integers and performs modular inversions. The block-cipher examples use indexed S-boxes; browser runtimes add JIT and memory-management behavior. These properties are useful for inspection and unsafe for handling valuable secrets. Use a reviewed implementation with an appropriate constant-time and platform strategy in real systems.

Consider timing, caches, branch predictors, speculative execution, power/EM leakage and fault injection according to the attacker’s access. Rejecting a bad point is not enough if key-dependent processing happened first. Authentication compares should avoid obvious early-exit behavior, but replacing one comparison does not make the whole program constant-time.

02 / FIELD NOTES

Randomness and exact parsing are part of implementation

Successful round trips can coexist with severe security bugs.

Generate keys/nonces with a CSPRNG and unbiased range sampling. Enforce scalar/point bounds, maximum message sizes, exact field widths, bit/byte units and strict DER structures. Track randomness failures and reinitialization. A statistical test suite can detect some defects, but passing randomness tests does not prove unpredictability of a generator or protection of its state.

High-level SM2 APIs may internally compute ZA and hash the message; low-level APIs may accept a digest. Verify which bytes the API consumes before hashing yourself. For symmetric APIs, explicitly select mode, IV/nonce, padding, tag length and associated data. API defaults can change across versions.

03 / FIELD NOTES

Acceleration support must be measured on the installed platform

An instruction name is not a guarantee for every build.

Optimized implementations may use dedicated instructions, SIMD, bitslicing/fixslicing or vectorized multi-buffer processing. AES and SM4 instruction support differs by architecture and CPU feature set; GCM adds another authentication workload. Check runtime feature detection and provider dispatch instead of assuming a platform can accelerate every GM primitive.

A meaningful performance comparison fixes cipher/mode, key size, payload sizes, message counts, setup reuse, CPU, compiler flags and library version. Keep test vectors, independent-library checks, protocol interoperability and product assurance as separate validation records.
