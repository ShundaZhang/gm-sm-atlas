SM2 加密
机制与实现

KDF、C1/C2/C3、完整性检查及密文编码

C1、C2、C3 功能不同验证 C3 前不能释放明文原始拼接与 ASN.1 不能互换
01 / FIELD NOTES

C1、C2、C3 功能不同

加密组合临时 ECC、KDF 与完整性摘要。

Validate recipient public key PB
fresh k∈[1,n−1]; C1=[k]G
(x2,y2)=[k]PB
t=KDF(x2 || y2, bit_length(M)); retry if t is all zero
C2=M XOR t
C3=SM3(x2 || M || y2)
Teaching wire profile: uncompressed C1 || C3 || C2

C1 让接收方以私钥重建共享点，C2 携带加密字节，C3 检查恢复明文及共享坐标。SM2 加密不以 SM2 签名的方式使用 ZA；给签名 API 设置 ID 不会配置加密认证。向公钥加密也不能证明发送者身份。

02 / FIELD NOTES

验证 C3 前不能释放明文

解密检查结构、点有效性与恢复数据。

Validate C1 and protocol-required cofactor/subgroup conditions
(x2,y2)=[dB]C1
t=KDF(x2 || y2, bit_length(C2)); reject all-zero t
M=C2 XOR t
u=SM3(x2 || M || y2)
Compare u with C3; only then return M

KDF(Z,klen): SM3(Z || ct), ct=00000001,00000002,…
Concatenate and truncate to klen bits

KDF 计数器为四字节大端，从一开始。域元素使用固定宽度，删除前导零会改变所有结果。教程 API 使用字节长度，仅支持字节对齐消息。生产协议应定义边界、错误处理及拒绝时间，避免形成解密预言机。

03 / FIELD NOTES

原始拼接与 ASN.1 不能互换

历史库中可见 C1C2C3 与 C1C3C2。

部分旧描述及 API 输出 C1C2C3；现代配置和库可能选择 C1C3C2 或 ASN.1。本项目明确使用 04||x1||y1||C3||C2。OpenSSL 测试会转为含 x1、y1、C3、C2 的 DER 结构，不假设相同字节数组到处通用。每个边界都应列明标准 / 配置及编码。

ECDSA 是签名方案，没有对应加密功能。应将 SM2 加密与完整定义的 ECC 加密或封装 + AEAD 设计对比，而非只与“NIST P-256”对比。大数据协议常用混合加密，但 KDF、关联数据和密钥分离必须由明确构造定义。
