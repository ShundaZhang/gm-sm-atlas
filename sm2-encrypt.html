01 / FIELD NOTES

C1, C2 and C3 do different jobs

Encryption combines ephemeral ECC, a KDF and an integrity digest.

Validate recipient public key PB
fresh k∈[1,n−1]; C1=[k]G
(x2,y2)=[k]PB
t=KDF(x2 || y2, bit_length(M)); retry if t is all zero
C2=M XOR t
C3=SM3(x2 || M || y2)
Teaching wire profile: uncompressed C1 || C3 || C2

C1 lets the receiver reconstruct the shared point using its private scalar. C2 carries encrypted bytes. C3 checks the recovered plaintext and shared coordinates. SM2 encryption does not use ZA in the way SM2 signatures do; adding an ID to a signature API does not configure encryption authentication. Encryption to a public key also does not prove who the sender is.

02 / FIELD NOTES

Do not release plaintext before C3 verification

Decryption checks structure, point validity and recovered data.

Validate C1 and protocol-required cofactor/subgroup conditions
(x2,y2)=[dB]C1
t=KDF(x2 || y2, bit_length(C2)); reject all-zero t
M=C2 XOR t
u=SM3(x2 || M || y2)
Compare u with C3; only then return M

KDF(Z,klen): SM3(Z || ct), ct=00000001,00000002,…
Concatenate and truncate to klen bits

The KDF counter is four-byte big-endian and starts at one. Field values use fixed widths; dropping leading zeros changes every result. The tutorial API takes lengths in bytes and supports byte-aligned messages only. A production protocol must define bounds, error handling and rejection timing to avoid creating a decryption oracle.

03 / FIELD NOTES

Raw concatenation and ASN.1 are not interchangeable

C1C2C3 and C1C3C2 can both appear in historical libraries.

Some older descriptions and APIs output C1C2C3; modern profiles and libraries may select C1C3C2 or an ASN.1 structure. This project explicitly uses 04||x1||y1||C3||C2. Its OpenSSL test converts to a DER structure containing x1, y1, C3 and C2, instead of assuming that the same byte array works everywhere. State the exact standard/profile and encoding at each boundary.

ECDSA is a signature scheme and provides no encryption equivalent. Compare SM2 encryption with a fully specified ECC encryption or encapsulation-plus-AEAD design, not with “NIST P-256” alone. Large-data protocols often use hybrid encryption, but their KDF, associated data and key separation require a defined construction.
