01 / FIELD NOTES

Four 32-bit words rotate through a 32-round core

SM4 has one standardized key length: 128 bits.

Input block: X0,X1,X2,X3 (big-endian 32-bit words)
For i=0..31:
 Xi+4 = Xi XOR T(Xi+1 XOR Xi+2 XOR Xi+3 XOR rki)
 T = L ∘ τ
 τ: apply the fixed 8-bit SM4 S-box to each byte
 L(B)=B XOR ROTL(B,2) XOR ROTL(B,10)
      XOR ROTL(B,18) XOR ROTL(B,24)
Output: X35 || X34 || X33 || X32

SM4 is commonly described as a generalized Feistel-type word structure. The final reversal is part of encryption, not an optional byte-order choice. The S-box is not the AES S-box. A 128-bit plaintext plus a 128-bit key always produces a 128-bit block; there is no padding inside the primitive.

02 / FIELD NOTES

The key schedule uses a different linear transform

L and L′ must not be mixed.

K0..K3 = MK0..MK3 XOR FK0..FK3
FK = a3b1bac6 56aa3350 677d9197 b27022dc
CKi,j = ((4i+j)×7) mod 256, j=0..3
CKi = four CK bytes in big-endian order
Ki+4 = Ki XOR T′(Ki+1 XOR Ki+2 XOR Ki+3 XOR CKi)
T′ = L′ ∘ τ
L′(B)=B XOR ROTL(B,13) XOR ROTL(B,23)
rki = Ki+4

Data rounds and key expansion share the byte S-box but use different rotations. Encryption applies rk0 through rk31; decryption uses the same round transform with rk31 through rk0, followed by the same output reversal. An inverse S-box is not required for SM4 decryption.

Trace a standard single-block known answer

This is a primitive test, not an ECB data-encryption recommendation.

Key   = 0123456789abcdeffedcba9876543210
Input = 0123456789abcdeffedcba9876543210
rk0   = f12186f9
X4    = 27fad345
Output= 681edf34d206965e86b3e94f536e4246

The lab shows all 32 round keys and generated words, then checks decryption with reversed keys. Independent OpenSSL tests use several different keys and blocks as well as the published example. Table-based S-box lookups are easy to read but can leak through caches; mathematical correctness does not establish constant-time behavior.
