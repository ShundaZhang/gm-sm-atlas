01 / FIELD NOTES

可读参考代码与生产代码用途不同

功能正确不证明抗泄漏能力。

下载的仿射 ECC 实现按标量位分支，使用变时 Python 整数并求模逆。分组示例使用索引 S 盒；浏览器运行时还加入 JIT 与内存管理行为。这些特征便于观察，不适合处理有价值秘密。真实系统应使用经审查、具有适当恒定时间及平台策略的实现。

应按攻击者接触能力分析时间、缓存、分支预测、瞬态执行、功耗 / 电磁及故障注入。若先发生密钥相关处理，之后拒绝坏点仍不足够。认证比较应避免明显提前退出，但替换一项比较不能让整个程序恒定时间。

对应资料：OpenSSL 3.5 · SM2 API ↗ · GmSSL · upstream implementation ↗ · NIST SP 800-56A Rev.3 ↗

02 / FIELD NOTES

随机数与精确解析属于实现

往返成功仍可能存在严重安全漏洞。

应以 CSPRNG 及无偏区间采样生成密钥 / Nonce；强制标量 / 点范围、最大消息长度、精确域宽、位 / 字节单位及严格 DER 结构。应处理随机源失败与重新初始化。统计测试可发现部分缺陷，但通过测试不证明生成器不可预测或状态受保护。

高层 SM2 API 可能内部计算 ZA 并哈希消息，低层 API 可能接收摘要。自行哈希前须确认 API 接收哪些字节。对称 API 应明确模式、IV / Nonce、填充、标签长度及关联数据；默认值可能随版本变化。

对应资料：OpenSSL 3.5 · SM2 API ↗ · OpenSSL 3.5 · SM3 digest ↗ · OpenSSL 3.6 · SM4 cipher ↗ · NIST SP 800-57 Part 1 Rev.5 ↗

03 / FIELD NOTES

加速支持应按实际安装平台测量

指令名称不是每种构建的保证。

优化实现可使用专用指令、SIMD、bitslicing / fixslicing 或向量化多缓冲处理。AES 与 SM4 指令支持随架构和 CPU 特征不同；GCM 还增加认证负载。应检查运行时特征检测及 Provider 分派，不假定平台能加速所有国密原语。

有意义的性能比较应固定密码 / 模式、密钥大小、负载长度、消息数、设置复用、CPU、编译参数及库版本。标准向量、独立库检查、协议互操作和产品保障应分别保留验证记录。

对应资料：Zhaoxin · GM algorithm families ↗ · GmSSL · upstream implementation ↗ · OpenSSL 3.6 · SM4 cipher ↗
