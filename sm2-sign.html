01 / FIELD NOTES

ZA binds identity, domain and public key

The digest is not just SM3(message).

ZA = SM3(ENTLA || IDA || a || b || xG || yG || xA || yA)
e  = integer(SM3(ZA || M))
ENTLA = 16-bit big-endian bit length of IDA
All field elements above: fixed-width big-endian octets

IDA is a protocol-defined byte string, not an implicit operating-system username. For a 16-byte ASCII ID, ENTL is 128 bits: 00 80, not 00 10. For UTF-8, count encoded bytes and then multiply by eight. Changing the ID, public key or domain changes ZA; signer and verifier must use the same context. A default ID from one library is not universally mandated for every protocol.

02 / FIELD NOTES

Read the signing and verification equations together

SM2 signatures are not ECDSA signatures on a renamed curve.

Sign, d∈[1,n−2], fresh k∈[1,n−1]:
(x1,y1) = [k]G
r = (e + x1) mod n
retry if r=0 or r+k=n
s = ((1+d)⁻¹ × (k−r d)) mod n
retry if s=0

Verify, first check r,s∈[1,n−1] and valid PA:
t = (r+s) mod n; reject t=0
(x1′,y1′) = [s]G + [t]PA; reject infinity
accept iff (e′+x1′) mod n = r

The signing key excludes n−1 because (1+d) would have no inverse mod n. The verification equation works because s+(r+s)d = k mod n. A public-key multiplication routine is shared ECC machinery; the surrounding signature equation remains distinct.

03 / FIELD NOTES

Nonce reuse exposes a private scalar

Secure randomness is part of the algorithm’s implementation.

For reused k and two valid SM2 signatures:
s1 + (s1+r1)d = k mod n
s2 + (s2+r2)d = k mod n
d = (s2−s1) / (s1+r1−s2−r2) mod n
when the denominator is invertible

Nonce bias, partial leakage and a side channel can also be dangerous without exact reuse. Do not transplant ECDSA’s deterministic-nonce procedure without a specified, analyzed SM2 construction. Fixed nonces in the downloadable tests are public synthetic values to reproduce equations, never a deployment recommendation.

Signatures are a pair (r,s), often encoded either as fixed 32+32-byte values or a DER SEQUENCE of two INTEGERs. DER INTEGER is signed: a leading 00 may be needed, so DER length is variable. Identity/digest mismatch, double hashing, key type confusion and raw/DER confusion cause common interoperability failures.
