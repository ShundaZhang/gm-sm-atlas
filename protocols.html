01 / FIELD NOTES

Four algorithm decisions occur in a TLS handshake

A TLS 1.3 cipher suite does not name the signature algorithm.

LayerRFC 8998 identifier / job
Record AEAD + handshake hashTLS_SM4_GCM_SM3 (0x00C6); TLS_SM4_CCM_SM3 (0x00C7)
SignatureSchemesm2sig_sm3 (0x0708)
Supported group / KeySharecurveSM2 (41 / 0x0029)
Certificate trustSeparate certificate, chain, identity, validity and policy checks

RFC 8998 specifies SM algorithms within TLS 1.3; it is not a generic “turn on GM” switch for every browser or TLS library. Certificate key type, transcript signature, negotiated group and record AEAD must all be compatible with the exact profile. A successful SM2 primitive test does not prove a complete TLS handshake will interoperate.

02 / FIELD NOTES

The protocol determines SM2 identity context

Handshake signatures and certificate verification can use different IDs.

RFC 8998 defines a TLS-profile ID TLSv1.3+GM+Cipher+Suite for its specified handshake uses and discusses the common 1234567812345678 value for peer-certificate verification, while noting CA-specific variation. Do not hard-code one ID into every signature operation. Match the certificate issuer’s profile and the handshake role.

An SM2 public-key OID, an sm2-with-SM3 signature OID and the TLS SignatureScheme are separate identifiers. A raw 64-byte signature may need DER encoding at another interface. Correctly parsing a certificate does not establish trust in its issuer or confirm the peer’s hostname.

Read the source: RFC 8998 · SM cipher suites for TLS 1.3 ↗ · RFC 5280 · X.509 ↗ · OpenSSL 3.5 · SM2 API ↗

03 / FIELD NOTES

TLCP is an independent transport protocol direction

Sharing primitives does not imply sharing the handshake.

GB/T 38636-2020 defines TLCP. Its handshake and certificate/key roles must be read from that protocol and selected profile; deployments can use distinct signing and encryption certificate roles. Do not copy those assumptions into TLS 1.3, or describe TLCP merely as TLS 1.3 with SM4 substituted for AES.

For interoperability, record the library/version, protocol version, cipher suite, group, identity bytes, certificate roles, trust anchor and encoding. Compare actual negotiated values and rejection logs, not a marketing label saying the endpoint supports SM2/3/4.
