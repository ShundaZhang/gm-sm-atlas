01 / FIELD NOTES

SM9 changes how users obtain private keys

A public identity is combined with system parameters and a key-generation authority.

SM9 is identity-based public-key cryptography. A key generation centre (KGC) holds a master secret and derives a user’s private key from an identity and the relevant algorithm domain. A verifier or encryptor uses the identity together with master public parameters; the identity is not secretly converted into an ordinary SM2 key pair by the user.

The family includes signatures, exchange, key encapsulation and encryption. Identities need a defined byte representation, domain, lifecycle and renewal/revocation policy. Embedding a validity period in an identifier changes the key namespace; it does not automatically implement a complete revocation system.

02 / FIELD NOTES

Pairings are more than ordinary ECC scalar multiplication

SM9 uses different groups and extension-field arithmetic.

Pairing: e : G1 × G2 → GT
Bilinearity: e([a]P,[b]Q)=e(P,Q)^(ab)
Implementation layers: base field → extension fields → curve groups
                      → pairing / final exponentiation → scheme

The standardized SM9 parameters use a pairing-friendly BN curve with embedding degree 12. G1, G2 and GT have different representations and operations. A point in G2 is not simply another curveSM2 public key, and a target-group value is not a point with two 32-byte coordinates. Production validation must follow the exact group, subgroup and encoding rules.

A 256-bit pairing-friendly base field cannot be assigned the same strength as P-256 merely by counting bits: attacks also involve the target extension field. Read current pairing cryptanalysis and the chosen parameter set. This atlas does not claim a universal numerical security level for SM9 from its field size.

03 / FIELD NOTES

KGC simplifies one trust problem and adds another

Master-key compromise has a wide blast radius.

A KGC can derive user private keys in its domain; the trust model therefore includes key escrow or an equivalent authority assumption. Protect the master secret, enrollment, distribution and renewal channels. Knowing that a message matches an identity does not prove that its private key was exclusively controlled by the named person.

SM2 users usually generate their own key pairs and use external certificates or directories for identity binding. SM9 moves that binding into an identity-based system, with different authority and revocation consequences. Neither approach is inherently post-quantum: their algebraic assumptions remain exposed to sufficiently capable quantum algorithms.
